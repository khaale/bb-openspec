## Context

См. proposal.md и согласованный макет docs/mockups/openspec-browser-v2.html. Репозиторий новый; установлен bb с Plugin SDK 0.6.79. Источник может находиться на любой подключённой машине, а разные окружения одного проекта содержат разные файлы.

## Goals / Non-Goals

**Goals:** самостоятельный TypeScript/React плагин, использующий публичный SDK, стандартные компоненты bb и существующее окружение для запуска тредов.

**Non-Goals:** собственный task tracker, зависимость от Tasks, изменение файлов через UI, доска, создание/архивация change, новые worktree, выполнение команд OpenSpec из плагина, пользовательские схемы артефактов в первой версии.

## Decisions

- Плагин располагается в корне проекта, чтобы его собственный openspec был доступен для проверки. Scaffold создаётся через bb plugin new.
- Чтение файлов через bb.sdk.files с явными hostId и rootPath выбранного environment. Стандартная структура proposal.md, design.md, tasks.md, specs/**/spec.md читается без зависимости от наличия CLI OpenSpec на сервере. Первая версия поддерживает стандартную структуру spec-driven; пользовательские schema не интерпретируются как фиксированный workflow.
- Чеклист разбирается отдельно от транспорта; учитываются Markdown-ограждения и завершение маркером x/X. Содержимое репозитория не изменяется плагином.
- Панель использует проект/окружение из контекста bb с возможностью явного выбора. При смене источника устаревшие асинхронные ответы не заменяют новые данные.
- Пока панель видима, обновлять данные раз в 5 секунд и по ручному запросу. Это покрывает изменения агентом без развёртывания отдельного host worker только ради filesystem watcher. Таймер освобождается при размонтировании, скрытая страница не опрашивается.
- Связь хранится в plugin metadata треда: environmentId и change id. Содержимое change и прогресс в базе не копируются. Привязка не запускает ход.
- Запуск через threads.spawn в существующем environment, с plugin metadata и явным пользовательским подтверждением. Настройки провайдера/модели/разрешений выбираются стандартными picker-компонентами SDK с маршрутизацией по окружению; значения по умолчанию берутся из bb.
- Markdown показывает стандартный компонент bb. UI использует theme tokens, Unicode-статусы и плотность согласованного макета. Служебные пояснения об источнике и трактовке статусов не выводятся на основной экран.

## Risks / Trade-offs

- Периодическое чтение создаёт нагрузку → только открытая видимая панель, ограниченные списки/размеры файлов; ручное обновление при необходимости.
- Большие изменения → явная ошибка превышения ограничения вместо молчаливого усечения документа; limits документируются.
- Запуск нового треда может начать изменение файлов → форма показывает первое сообщение и окружение, настройки разрешений контролирует bb.
- Архивное изменение доступно для просмотра, запуск агента отключён; связь архива с прежним именем не выводится предположительно.

## Migration Plan

Локальная установка текущей директории после сборки и проверок. Откат — отключение/удаление плагина; исходные файлы OpenSpec не изменяются. Новая версия не требует миграции данных.

## Why

Плагин сейчас читает только openspec/ выбранного checkout. В store-only проектах изменения находятся в отдельном зарегистрированном store, поэтому браузер показывает пустой список и не может корректно передать агенту контекст.

## What Changes

- Разделить окружение выполнения и источник планирования: автоматический выбор OpenSpec, явный локальный источник или зарегистрированный store на той же машине.
- Определять источники через JSON CLI OpenSpec при открытии/смене источника и ручном обновлении, сохранив прямое чтение и native watcher для содержимого и прогресса.
- Передавать источник в RPC, просмотр файлов, запуск агентов и metadata привязки; одинаковые change id разных stores не смешиваются.
- Показать источник в свёрнутой шапке и выборе контекста; ошибки регистрации/CLI доступны в интерфейсе.
- Сохранить repo-local режим без CLI для обычных локальных openspec/specs или changes.

## Capabilities

### New Capabilities

- `openspec-store-sources`: разрешение источника OpenSpec, выбор stores, изоляция привязок и агентный контекст.

### Modified Capabilities

Нет: предыдущие возможности пока описаны в незархивированных changes.

## Impact

Host RPC и индекс/watcher, backend RPC и metadata треда, frontend выбора источника/документов/запуска, тесты и документация. CLI нужен для stores; зависимости на внутренние модули OpenSpec не добавляются. Плагин не регистрирует stores, не меняет пользовательские configs и не выполняет git sync. Worksets и просмотр общего каталога upstream specs не входят в этот change; references остаются контекстом стандартных workflow CLI.

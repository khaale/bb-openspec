## ADDED Requirements

### Requirement: Разрешение источника независимо от окружения выполнения
Плагин SHALL определять источник на машине выбранного окружения через публичный JSON CLI OpenSpec. Автоматический выбор SHALL соответствовать context, включая store-only и defaultStore; явный store SHALL передаваться через --store. Явный локальный выбор SHALL читать openspec/ выбранного окружения.

#### Scenario: Проект store-only
- **WHEN** config проекта указывает зарегистрированный store и локальные planning directories отсутствуют
- **THEN** автоматический выбор показывает changes store, оставляя execution environment кодового проекта

#### Scenario: Проект store-optional
- **WHEN** локальные planning directories существуют и пользователь явно выбирает store
- **THEN** браузер читает выбранный store вместо локального источника

#### Scenario: Отсутствующий CLI или неисправный store
- **WHEN** источник store невозможно разрешить
- **THEN** интерфейс показывает ошибку без подмены выбранного store локальным источником
- **AND** обычный локальный источник с planning directories доступен без CLI

### Requirement: Чтение и наблюдение выбранного источника
Плагин SHALL читать только артефакты выбранного change внутри разрешённого planning root. Содержимое SHALL читаться напрямую, без CLI на каждое файловое событие. Watcher SHALL разделяться по planning path и освобождаться при закрытии последней подписки. Ручное обновление SHALL повторять discovery и восстанавливать наблюдение нового пути.

#### Scenario: Изменение общего внешнего store
- **WHEN** несколько окружений наблюдают один store и агент меняет tasks.md
- **THEN** панели получают актуальный прогресс через общий watcher
- **AND** чтение кешированного списка и idle не вызывают CLI

#### Scenario: Смена регистрации store
- **WHEN** пользователь меняет registration и нажимает обновление
- **THEN** источник разрешается заново и наблюдение переключается на актуальный путь

### Requirement: Привязка тредов к источнику планирования
Привязка SHALL включать environmentId, changeId и фактически разрешённый storeId. Одинаковые changeId разных источников SHALL иметь независимые списки тредов. Существующие привязки без storeId SHALL оставаться локальными.

#### Scenario: Запуск и перепривязка между источниками
- **WHEN** пользователь запускает или привязывает тред к store change
- **THEN** metadata фиксирует store, панель треда восстанавливает его, а локальный change с тем же id не получает эту связь
- **AND** запуск переиспользует кодовое окружение и передаёт агенту planning path и --store

### Requirement: Компактный выбор источника
Шапка SHALL отображать текущий store в свёрнутом контексте, а раскрытый выбор SHALL предлагать Auto, локальный источник и зарегистрированные stores. Просмотр исходного внешнего файла SHALL открывать его на host store, а не относительно code checkout.

#### Scenario: Открытие документа store
- **WHEN** пользователь выбирает store и открывает артефакт
- **THEN** Markdown и file preview используют путь store, а controls проекта/окружения сохраняют execution context

### Requirement: Активные и свежие изменения первыми
Список changes SHALL размещать изменения с active тредом первыми, затем сортировать по убыванию mtime артефактов. Алфавит SHALL разрешать только совпадения. Статусы тредов и файловые события SHALL обновлять порядок без ручного refresh.

#### Scenario: Новая работа выше старых завершённых changes
- **WHEN** новый change создан или к нему привязан работающий агент
- **THEN** он отображается выше старых изменений независимо от алфавитного имени

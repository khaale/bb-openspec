## Context

См. proposal.md. SDK 0.6.79 предоставляет host native watch, сигналы host → server и experimental_whileWatched с временем жизни до последнего клиента. Первая версия плагина опрашивает три read-запроса каждые 5 секунд.

## Goals / Non-Goals

**Goals:** убрать idle I/O; читать файлы на машине проекта; разделять обновления файлов, документов и тредов; освобождать ресурсы при закрытии панелей.

**Non-Goals:** фоновая индексация всех проектов, постоянная база/кэш на диске, запуск CLI на каждое событие, изменение данных praxis/lore.

## Decisions

- Frontend переводит changes/detail/document на штатные experimental_useRpcQuery. Contract tags определяют точечные invalidation. Самописный таймер удаляется.
- experimental_whileWatched(changes) управляет host watcher. Один индекс на рабочую директорию разделяется наблюдателями. Идентификатор подписки нужен для безопасного освобождения при перекрывающихся mount/unmount и отмене RPC.
- Host native watch объединяет события сохранения; индекс хранит список файлов, разобранные tasks и summaries только пока есть наблюдатели. При обновлении известного файла tasks перечитывается только он; изменение структуры пересканирует имена, сохраняя результаты для неизменившихся tasks.
- Содержимое Markdown документа по-прежнему читается с rootPath confinement; watcher инвалидирует только изменённый документ. Сигналы без полного списка путей вызывают rescan.
- При отсутствии openspec наблюдается его родитель с исключением остальных существующих entries; при появлении каталога watcher переключается на него. Это также покрывает удаление и пересоздание корня.
- Статусы тредов инвалидируются по событиям bb. Изменения metadata при привязке публикуются явно. Worker exit/host reconnect восстанавливают только существующие live subscriptions.
- CLI сравнивается как внешний процесс с отключённой telemetry. Первые замеры: около 340–350 мс на вызов; архивные change не поддерживаются status. Поэтому прямое чтение остаётся единственным production reader, без запасного CLI-пути и новой зависимости.

## Risks / Trade-offs

- Файловые события могут быть потеряны → rescan-required и reconnect восстанавливают состояние.
- Native watcher требует готовой машины → ошибки показаны через RPC; ручное обновление сохраняется, периодический polling не добавляется.
- Архив может быть большим → прежние лимиты сохраняются, неизменившиеся tasks не перечитываются.
- Несколько окружений могут ссылаться на одну директорию → host индекс разделяется по пути, invalidation маршрутизируется по environmentId каждой подписки.

- Список показывает пропорцию задач и зелёное «✓ Выполнено» при ненулевом полном checklist. Это статус задач, архив остаётся отдельной категорией.
- Компактный режим хранится в localStorage интерфейса: список карточек, переход в детали и возврат. Скрытые детали не поддерживают лишнюю подписку.
- Перепривязка обновляет tags списка, деталей и источника контекста треда; в выборе виден прежний change, поскольку у треда одна текущая привязка.
